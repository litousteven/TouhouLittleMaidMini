# Touhou Little Maid Mini `0.1.1-beta`

第二个公开测试版，仍然是 **pre-release**。相对 `0.1.0-beta` 的「被动 MCP」，本版把大脑
搬到玩家客户端：模型只提交「模块序列 + 参数」，Java 侧逐条校验后逐步执行；API Key 不再
进入服务端。同时加入自主模式与可审阅的计划模板学习闭环。

本版**只完成基础验收**；0.2 正式发布所需的两项门禁仍未关闭，详见下方「未关闭的发布门禁」。

## 适用版本

| 组件 | 版本 |
|---|---|
| Minecraft | `26.3` |
| 加载器 | Fabric Loader `0.20.1` 或更高 |
| Fabric API | `0.165.2+26.3` |
| Java | `25` |

下载 `touhou-little-maid-mini-fabric-26.3-0.1.1-beta.jar`，**客户端与服务端都要安装**。
安装与首次连接见
[`docs/07-installation.md`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.1-beta/docs/07-installation.md)。
本版只发布 Fabric jar；`neoforge` 可编译但未验证，不提供产物。

## 本版新增

- **客户端脑**：游戏内 `AI 设置` 填写 OpenAI 兼容 base URL / model / API Key，聊天面板
  驱动 Agent 循环；服务端不保存 Key、不发起模型请求，由
  `:fabric:verifyClientOnlyModel` 守护。`0.1.0-beta` 的服务端凭据文件与 `[llm]` 配置段
  不再读取（不删除、不打印用户文件），旧的 `/tlmm llm *` 命令已移除。
- **有界计划**：`PlanJson` → `PlanGate` → `PlanRuntime` 三处复验；模型不能生成代码，只能
  提交白名单模块的有序计划。区域农作、采集、放置、容器存取、槽位搬运、合成、熔炼、
  同类归并整理箱子、拾取掉落物等能力全部是 Java 预制的强类型模块。
- **自主模式**：`off / suggest / chores / free` 四档（默认 `chores`），六类机会识别，
  导演仲裁（威胁、受伤、操作者暂停优先于任何计划），运行预算与连续失败熔断，
  `/tlmm autonomy ...` 与 `/tlmm ai pause|resume|status`。自主计划只能使用档位策略，
  且必须回应服务端本轮给出的机会。
- **学习闭环**：成功的计划只生成**待审提案**；采纳后前两次执行仍需逐次确认，两次成功才升
  `trusted`，连续失败降级，回滚可撤销采纳。`/tlmm template ...` 与模板审阅界面由服务端
  推送全量视图，状态同步。
- **Skill 三级加载**：索引 / 正文 / 附属文件按需披露，路径越界、`..`、绝对路径、扩展名
  与 256KB 上限在 Java 侧强制。
- **语义与知识**：六档语义优先级、未知模组内容标注、人工确认、批次回滚与导出。
- **文本与打包**：中英双语 147 键一致；jar 内含 `core` / `mcp` / `llm`，打包完整性由
  `:fabric:verifyPackagedMod` 与 `scripts/verify-packaged-jar.py` 守护。

完整设计与逐条核对见
[`docs/validation/M6.md`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.1-beta/docs/validation/M6.md)，
分阶段记录见
[`M6.4`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.1-beta/docs/validation/M6.4.md)、
[`M6.5`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.1-beta/docs/validation/M6.5.md)、
[`M6.6`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.1-beta/docs/validation/M6.6.md)。

## 未关闭的发布门禁

以下两项按 `docs/02-development-plan.md` M6.7 与
[`docs/validation/M4.md`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.1-beta/docs/validation/M4.md)
只能由发布操作者在目标环境完成，本会话无法产生真实证据：

- **24 小时浸泡**：`scripts/soak.ps1 -Minutes 1440` 在目标专用服采样，确认无堆/线程趋势
  增长、无端口残留，4 名同伴并行计划时 MSPT 增量 < 1.0。现有 `soak-24h.csv` 只有
  2 小时，短时浸泡不能替代。
- **干净 VM**：按 README / 安装文档在全新环境 30 分钟内跑通。

此外，场景 A/B 的一次完整自主计划实跑尚未单独记录。因此本记录**不宣称 0.2 发布验收通过、
不创建 `v0.2` tag**，本版只作为基础验收后的功能预览供试用与反馈。若出现回归，会另发
pre-release 修正，而不是静默替换本版产物。

## 从 `0.1.0-beta` 升级

- **协议不兼容**：`agent_submit_plan` 增加 `source` / `tokens`，新增 S2C
  `agent_opportunities`、`template_view`，`agent_request_observation` 的 category 上限
  提到 256 并支持 `skill:` / `skill_file:`。客户端与服务端必须同步升级。
- **模型配置位置改变**：改在客户端 `AI 设置` 页填写，或写入客户端配置文件；服务端
  `config/tlmm/credentials.key` 与 `[llm]` 段被忽略。
- **新增配置与数据**：`config/tlmm-autonomy.toml`（档位，默认 `chores`）、
  `config/tlmm/learning/templates.json`、`config/tlmm/skills/`、`config/tlmm/knowledge/`。
  首次启动自动创建，可安全删除以重置学习状态。
- **新增命令**：`/tlmm autonomy ...`、`/tlmm ai ...`、`/tlmm template ...`。

## 已知限制

- 首发与主验证加载器是 Fabric；NeoForge 未验证、不发布产物。
- MCP 端点只监听回环地址，远程访问请用 SSH 隧道，不要把 `host` 改成公网地址。
- 自主模式依赖主人客户端在线；客户端退出后同伴只保留确定性基础行为。
- 模型不可用、断线或被拒绝时回到基础脑；`hostile` 类动作仍需人工确认。
- 完整列表见
  [`docs/09-known-limitations.md`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.1-beta/docs/09-known-limitations.md)。
