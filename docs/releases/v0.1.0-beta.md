# Touhou Little Maid Mini `0.1.0-beta`

首个公开测试版。同伴是「可以由 Agent 驱动、但仍然受服务端规则约束」的实体：模型、动画、
状态和动作全部走同一套 MCP 契约，控制权不在客户端。

## 适用版本

| 组件 | 版本 |
|---|---|
| Minecraft | `26.3` |
| 加载器 | Fabric Loader `0.20.1` 或更高 |
| Fabric API | `0.165.2+26.3` |
| Java | `25` |

下载 `touhou-little-maid-mini-fabric-26.3-0.1.0-beta.jar`，客户端与服务端都要安装。
安装、签发 Token 与首次连接见
[`docs/07-installation.md`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.0-beta/docs/07-installation.md)。

## 本版内容

- **同伴**：原创模型与皮肤、走路 / 待机 / 持弓动画、名字与状态行，右键打开 `176x240`
  管理界面（生命与饥饿图标、MCP 状态点、地址与 Token 提示）。
- **通用能力**：`companion_move`、`companion_interact` 等动作走统一工具注册表。配置里
  未启用的动作在注册表层就被过滤，不是解析后忽略；新增方块（例如从未见过的作物）不需要
  为它写专用动作。
- **MCP**：Streamable HTTP + Bearer Token。Token 按同伴签发、只存 SHA-256 摘要、可吊销；
  并发数、单 Token 频率、认证失败来源均有上限。
- **安全**：默认只监听回环地址，非循环 Origin 拒绝，跨玩家操作需要所有者确认，断线后按
  配置降级而不是继续执行未完成动作。
- **运维**：`/tlmm diag`、`ping` 健康快照（MSPT / 堆 / 线程 / 保留事件）、
  `scripts/e2e-mcp.ps1`、`scripts/soak.ps1`。
- **文本与配置**：中英双语 64 键由 `verifyTranslations` 守护；`config_version` 自动迁移，
  `[limits]`、`[actions]`、`[safety]` 分段。

## 尚未完成的发布门禁

以下两项没有目标环境证据，因此本版标记为 **pre-release**，不声称 M4 已完整验收：

- **24 小时浸泡**：`scripts/soak.ps1 -Minutes 1440` 在发布时仍在进行（起点
  `2026-11-21 15:25`，预计 `2026-11-22 15:25` 结束）。这一轮是空载
  （`companions=0`），只能证明 MCP 传输层与线程池不泄漏；满载数据来自 GameTest 探针。
- **全新 VM 按 README 复跑 30 分钟场景**：未执行。

若后续出现回归，会以新的 pre-release 修正，而不是静默替换本版产物。

## 已知限制

- 首发与主验证加载器是 **Fabric**。`neoforge` 模块可编译，但未在本版验证，因此不提供
  NeoForge 产物。
- MCP 端点只监听回环地址，不能从其他机器直接连接；远程访问请使用 SSH 隧道，不要把
  `host` 改成公网地址。
- 本机 AMD Vulkan 驱动在资源重载阶段偶发 `0xC0000005` / `0xC0000409` 原生崩溃，与模组
  逻辑无关，删除 `run/clientGametest/screenshots` 与 `options.txt` 后重试即可。
- 其余限制见
  [`docs/09-known-limitations.md`](https://github.com/litousteven/TouhouLittleMaidMini/blob/v0.1.0-beta/docs/09-known-limitations.md)。

## 产物修订（`2026-11-21`）

本版第一份 CI 产物只包含 `client` 与 `fabric` 的类，缺少 `core` 与 `mcp`：Gradle 不会把
项目依赖打进 jar。安装那份 jar 会在第一次引用 `core` 时崩溃。问题在发布后约十分钟内
发现，已修复并替换同一 tag 的附件，现在是 `103` 个类、引用完整性检查通过。旧产物无法
使用，因此选择直接替换而不是另发版本，在此记录。
