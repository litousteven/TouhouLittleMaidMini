# M6.6 学习闭环 — 验收记录

日期：2026-11-22
范围：`docs/10-autonomy-and-scripting.md` §12、`docs/02-development-plan.md` M6.6

## 结论

通过。「学习」只产出可审阅的数据：一次成功的计划生成一条提案，采纳后才成为可执行模板，
前两次执行都要主人确认，两次成功升为 trusted，连续三次失败降回 supervised，回滚可撤销
采纳。未经审阅的提案和已回滚的模板都不能执行。Skill 按索引 → 正文 → 附属文件三级加载，
目录边界和大小上限在 Java 侧强制。

## 交付

### `core/learning`：纯 Java 状态机

- `TemplateProposal`（PENDING / ADOPTED / REJECTED）、`PlanTemplate`、
  `TrustLevel`（SUPERVISED / TRUSTED / DISABLED）、`TemplateStep`（参数占位符 + 默认值）。
- `TemplateDraft`：从成功计划的 JSON 提炼模块序列，把 `x/y/z/item/seed/input/fuel/ids/
  text/material` 等易变参数替换成 `${name}` 占位符并保留默认值；单步、纯 `say`、
  非法 JSON 不产生提案。反向 `planJson(template, bindings)` 生成可被常规
  `PlanJson.parse` 接受的计划。
- `TemplateCatalog`：提案去重（目标 + 模块序列）、上限 32 提案 / 64 模板、采纳/拒绝/
  回滚、逐次确认、2 次成功升信任、3 连败降级。`executionDecision` 是唯一的「能不能跑」
  判定；`beginRun` 消费掉那一次确认。
- `TemplateCatalogJson`：严格读写 `config/tlmm/learning/templates.json`，坏行记为问题
  并丢弃，不会因一行脏数据把信任级别读错；写入走临时文件 + 替换。

### `fabric/learning` 与命令

- `TemplateService`：注册为 `PlanRuntime` 完成监听器。计划成功 → 生成提案；由模板启动的
  计划按 id 记账，成功/失败分别进入 `recordOutcome`。状态变化即落盘并推送审阅视图。
- `/tlmm template list|ui|propose <plan-json>|adopt|reject|rollback|confirm|run <id>`。
  写操作为 GM 级，`confirm` 供主人授权一次监督执行；界面按钮发的也是命令，权限路径唯一。
- `TemplateViewPayload`（S2C，≤32 行）+ `TemplateScreen`：提案显示「采纳/拒绝」，
  supervised 模板额外显示「确认」，trusted 不再显示确认按钮；服务端每次状态变化都推
  全量视图，界面不自己推断信任级别。

### `core/skill` 三级加载

- `SkillLoader(builtin, user)`：用户目录同名技能覆盖内置。**索引**只给 name +
  description；**正文**按 `skill:<name>` 请求；**附属文件**按
  `skill_file:<name>:<relative>` 请求。
- 每次读取 ≤256KB；名字限 `[a-z0-9_-]{1,64}`；相对路径拒绝 `..`、绝对路径、反斜杠，
  规范化后必须仍在 `<root>/<skill>/` 内；扩展名白名单 `.md/.txt/.json/.csv/.properties`。
- `SkillService` 在 `config/tlmm/skills/` 准备内置样例，`AgentObserver` 只在 `status`
  观察里附带索引；正文与附属文件走带限流的分类观察请求，不进常态上下文。
- `AgentServerPayloads.ObservationRequest` 的 category 上限由 32 提到 256，容纳
  `skill_file:` 路径。

## 验证

```
./gradlew :core:test :mcp:test :llm:test              → 276 个用例（core 182 / mcp 79 / llm 15），
                                                        0 失败、1 项按设计跳过
./gradlew :fabric:runGameTestServer                   → All 114 required tests passed
./gradlew :fabric:runClientGametest -Ptlmm.graphicsBackend=vulkan
                                                      → 模板审阅界面状态同步通过
./gradlew :fabric:verifyTranslations                  → 147 键一致
./gradlew :fabric:verifyClientOnlyModel               → 通过
./gradlew build                                       → 成功
```

核心新增单测 3 个类（`TemplateCatalogTest`、`TemplateDraftTest`、`SkillLoaderTest`），
服务端 GameTest 6 条、客户端 GameTest 1 条。

- 成功计划只产生一条待审提案、不产生可执行模板；失败计划不产生提案。
- 采纳后第一次执行被 `confirmation_required` 拦下；一次确认只能买一次执行。
- 真实跑一次模板计划 → 完成监听器记账 → `successes=1` 且仍是 supervised；
  第二次成功升 trusted；三次连续失败降回 supervised。
- 拒绝提案后待审数归零；回滚后模板 DISABLED、不可执行、原提案重新变为 PENDING。
- Skill：索引不含正文、正文可按需取、附属文件可读、`../secret.txt` 被拒且不泄漏内容。
- 客户端：推送「supervised」视图后注入「trusted」视图，界面状态与计数同步更新。
  两张验收截图见 [`assets/m6.6/`](assets/m6.6/)：监督态显示 Confirm 按钮，信任态不再显示。

## 已知限制

- 模板只记录模块序列与参数占位符，不做模型训练、不生成代码、不自动改写模块库；
  参数绑定目前只支持默认值与显式 Map，没有在聊天里用自然语言填参的交互。
- 内置 Skill 在首次启动时物化到 `skills/builtin/`，不是从 jar 资源直接读取；
  这样内置与用户覆盖共用同一个加载器，但升级时不会自动覆盖玩家改过的内置副本。
- 模板执行使用 `commandConfirmed()` 策略（采纳即授权），仍受 `PlanGate` 的全部静态
  限额与模块白名单约束。
