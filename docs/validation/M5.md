# M5 第一个双脑切片验收记录

日期：`2026-11-21`

范围：无模型基础脑、游戏内 LLM 配置、主动模型请求的最小安全闭环。

## 1. 参考调研

- 原版 [TartaricAcid/TouhouLittleMaid](https://github.com/TartaricAcid/TouhouLittleMaid) 默认分支 `1.20`。
- 模型配置参考：`config/subconfig/AIConfig.java` 与
  `ai/service/llm/openai/LLMOpenAISite.java`，确认需要 base URL、secretKey、model 列表和启用开关。
- 主动请求参考：`ai/manager/entity/MaidAIChatManager.java`，由实体事件触发，经
  `LLMCallback` 回到女仆行为。
- 基础脑参考：`entity/ai/brain/MaidBrain.java` 与
  `entity/ai/brain/task/`，确认 farming/follow/attack/await 是独立任务；本项目只借鉴分层，不复制类。

## 2. 已实现

- `core`：新增 `LlmConfig`（不含 Token）与 `LocalBehavior.FARM`。
- `llm`：新增纯 Java、OpenAI 兼容的最小 HTTP 客户端；响应只能解析为
  `stay/follow/guard/farm`、短反馈和可选 Skill 提案，不能输出命令、URL、脚本或工具名。
- `fabric`：
  - `[llm]` 配置自动补全；API Token 写入独立凭据文件，日志、审计和聊天不回显 Token。
  - 右键同伴的“AI”按钮打开配置界面；owner/OP 也可用 `/tlmm llm base|model|token|enabled|status`。
  - `LlmRuntime` 在服务端虚拟线程发起主动请求，限速、失败降级，决策回到服务端主线程执行。
  - 模型提出的 Skill 只保存到 `config/tlmm/learned-skills/*.md`，标记为 proposal，不自动执行。
  - `FarmGoal` 在无模型时按 `CropBlock` 语义收割成熟作物并用背包种子补种。
  - `guard` 目标判定覆盖“威胁主人”的附近怪物，同时保留玩家/村民/有主宠物保护。
- `fabric.mod.json`：注册 `M5BaselineGameTests`。

## 3. 验证命令与结果

```powershell
$env:JAVA_HOME="<repo>\.gradle-local\jdk-25.0.5.1+2"
$env:PATH="$env:JAVA_HOME\bin;$env:PATH"

.\gradlew.bat :core:test :mcp:test :llm:test :fabric:verifyTranslations build
.\gradlew.bat :fabric:runGameTestServer
.\gradlew.bat :fabric:runClientGametest '-Ptlmm.graphicsBackend=vulkan'
```

结果：

- 单元测试、`verifyTranslations`（74 键一致）与全仓构建通过；jar 包含 `core`、`mcp`、`llm` 包。
- `:fabric:runGameTestServer`：`50 tests ... All 50 required tests passed`。新增
  `farmBehaviorHarvestsAndReplantsWithoutAgent` 证明无模型也能收割并补种。
- 客户端 GameTest 通过；截图 `run/clientGametest/screenshots/0001_m4-companion-screen.png`
  已人工检查，顶部“AI”按钮完整、未与 Copy 或标题重叠。
- 模型请求逻辑由 `LlmClientTest` 的模拟传输覆盖；未使用真实 API Token 或外部网络。

## 4. 仍未完成

- 模型尚不能直接生成多步动作序列来建造、开垦、识别模组材料或操作工作台；目前只映射四种本地行为并产出 Skill 提案。
- Skill 提案没有自动审阅 UI，需人工移动/确认后才能成为可执行 Skill。
- 没有真实 OpenAI 兼容服务的端到端调用测试；插件 API 差异需按具体服务商验证。
- Token 通过命令写入时，若服务器显式开启了命令日志，仍可能出现在外部日志中；配置目录权限由操作者负责。
- NeoForge 不随本切片更新。

## 5. 结论

**基础脑与配置 UI：Go。**

**模型主动请求的安全最小闭环：Go（仅行为决策与 Skill 提案）。**
**模型驱动建造/开垦/工作台：No-Go，留待后续带动作执行器和权限确认的切片。**
