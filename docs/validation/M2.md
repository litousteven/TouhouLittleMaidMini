## 2. 已验证行为

- `initialize` 返回 `2025-11-25` 与 `serverInfo`。
- `tools/list` 返回 10 个工具、JSON Schema 与 annotations。
- 参数校验：缺失、类型错误、未知参数、数值下限均返回 `invalid_params`。
- 未知工具 → `unknown_tool`；未知方法 → `-32601`。
- 未知同伴 → `unknown_companion`（不再落到 `internal_error`）。
- 无 Token / 错误 Token → HTTP 401。
- Token 作用域：`TLMM_MCP_READ_ONLY=1` 时写工具返回 `scope_denied`。
- 审计：每请求一行，仅含 request id、token 摘要、工具名、companion、状态、
  code、耗时；不含 Token 本体、背包或聊天正文。
- 幂等：相同 `request_id` 重放返回缓存结果，不二次执行。
- 事件：`behavior_changed`、`operation_stopped` 单调递增；游标越界报
  `event_cursor_expired`。
- 服务器线程：所有世界操作经 `runOnServer` 提交主线程并等待，HTTP 线程不直接改世界。
- 停服：一次运行内 `[mcp] listening` → `[mcp] stopped`，端口释放。

## 4. `companion_interact` 的实现方式

一个早期的错误结论是"Minecraft 26.3 要求 Player 上下文，所以同伴无法交互"。这个结论
只看了 `useItemOn` / `useWithoutItem`，是错的。

正确的依据来自原版自己：村民的 `HarvestFarmland` 也是非玩家实体，它收获作物用的是

```java
ServerLevel.destroyBlock(BlockPos pos, boolean dropItems, Entity entity)
```

该入口接受任意 `Entity`，同伴实体同样适用。当前实现：

1. 目标方块必须是 `CropBlock`。
2. `CropBlock.isMaxAge` 判断成熟；未成熟返回 `not_ready`，不改动方块。
3. 成熟时调用 `destroyBlock(pos, true, companion)` 收获并掉落。
4. 发布 `operation_completed` 事件，返回 `harvested`。

当前不支持的其他方块交互（例如模组机器、按钮、容器）返回
`unsupported_interaction`，而不是伪造成功。

GameTest 覆盖：

- `companionHarvestsAFullyGrownCrop`：成熟小麦被收获，方块变空。
- `immatureCropIsRefusedWithNotReady`：未成熟作物被拒绝且不被破坏。
