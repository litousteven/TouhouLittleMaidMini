# M6.3 语义底座验收

日期：`2026-11-21`

范围：`SemanticTag` 封闭枚举、六档优先级解析器、真实数据/标签/启发式来源、知识文件读写与
冲突校验，以及 `FarmGoal`、`harvest_area` 从硬编码 `CropBlock` 迁移到统一解析器。

## 1. 实现

`core/semantic`（纯 Java，无 Minecraft 依赖）：

- `SemanticTag`：17 个值，每个声明允许的 `kind`；材料类标签（log / plank / stone / ore /
  building_block）互斥，用于冲突判定。
- `SemanticSource`：`DATA → TAG → USER → MODEL → HEURISTIC → UNKNOWN`，序号即优先级。
- `SemanticTags`：唯一解析入口；真实数据与真实标签不可被覆盖。
- `RealFacts`：由加载器提供 `exists / realData / realTags / heuristic` 三组答案。
- `KnowledgeValidator`：`unknown_id`、`kind_mismatch`、`bad_tag`、`tag_conflict`、
  `user_locked`；`confidence < 0.6` 降级为 `pending`，不生效。
- `KnowledgeFile`：按 namespace 分文件，`entries` / `pending`，写入走临时文件 + 原子替换。
- `KnowledgeStore`：加载时逐条校验，坏行只计数不整批失败；支持按 `batch` 整批回滚。

`fabric/semantic`：

- `FabricRealFacts`：
  - 物品：`FOOD` / `COOKING_FUEL` / `TOOL` 组件；`#minecraft:logs` / `planks` / `c:ores`。
  - 方块：`#minecraft:crops` / `logs` / `planks` / `c:ores`；`CropBlock` / `StemBlock` 启发式；
    容器与工作站需要放置后的方块实体（`Container`、熔炉、合成器、锻造台）。
  - 实体：`Monster` → `hostile`；`Animal` → `livestock` + `breedable`。
- `SemanticService`：服务端启动时读取 `config/tlmm/knowledge/`，提供 `resolve(BlockState /
  ItemStack / Entity)`；停止时清空。
- `CropShape`：`age` 属性与成熟判定，供目标与模块共用。

行为迁移：

- `FarmGoal` 不再出现 `CropBlock`：候选方块带 `age` 属性即进入解析器；未分类时发布
  `unknown_category`（每个 id 一次）并跳过，不静默忽略。
- `harvest_area` / `plant_area` / `till_area` 的种子选择与成熟判断改走 `SemanticTags` +
  `CropShape`；`harvest_area` 在没有成熟作物但存在未分类的 `age` 方块时返回
  `unknown_category`。

## 2. 验证

```powershell
.\gradlew.bat :core:test :mcp:test :llm:test
.\gradlew.bat :fabric:verifyTranslations build
.\gradlew.bat :fabric:runGameTestServer
```

结果：

- 单元测试：`core 101` / `mcp 79` / `llm 3`，共 183 个，0 失败。新增
  `SemanticTagsTest`（优先级、覆盖规则、`unknown_category`）与 `KnowledgeStoreTest`
  （四类拒绝码、`user_locked`、低置信度 pending、文件往返、冲突行忽略、坏文件、批次回滚）。
- `verifyTranslations`：78 键一致；全仓 `build` 成功。
- GameTest：`82 GAME TESTS COMPLETE` / `All 82 required tests passed`，连续三次运行一致。
  新增 5 条：
  - `heuristicsClassifyVanillaAndTestCrops`：小麦来自 `#minecraft:crops`（`source=TAG`），
    测试作物来自 `CropBlock` 启发式（`source=HEURISTIC`）。
  - `unknownAgeBlockIsReportedAndNotHarvested`：甜浆果丛无分类 → 发布
    `unknown_category`，`FarmGoal` 不把它当目标，方块保持原样。
  - `knowledgeEntryMakesUnknownBlockFarmable`：写入 `minecraft:nether_wart` → `crop`
    的知识文件后，`harvest_area` 计划真的把它收掉（说明知识层能改变行为）。
  - `vanillaCropsRemainHarvestableWithoutKnowledge`：没有知识文件时小麦仍可识别。
  - `knowledgeDirectoryIsUnderConfig`：路径固定为 `config/tlmm/knowledge`。

## 3. 已知边界

- 容器/工作站启发式需要已放置的方块实体；纯注册表查询无法判断，因此对背包里的方块物品
  不会给出 `container` / `station`。
- `hostile` 的硬排除名单（玩家、村民、有主宠物）仍由 `guard` 目标判定负责，语义层只标类别。
- 知识文件没有审阅 UI 与扫描入口，属于 `M6.3b`；当前只能手工编辑文件或由测试写入。
- 真实标签与数据永远优先；玩家想覆盖只能改数据包，不能用知识文件。

## 4. 结论

**Go**：语义判断收敛到单一解析器，无模型时启发式可用，未知内容显式失败，冲突条目被忽略。
