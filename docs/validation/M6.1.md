# M6.1 身体能力验收

日期：`2026-11-21`

范围：挖掘、放置、容器读写、槽位搬运、合成、熔炼，以及工具前置与耐久。

## 1. 实现

全部以动作模块形式提供，复用 M6.0 的闸门、预算与事件：

| 模块 | 风险 | 要点 |
|---|---|---|
| `dig_block` | `DESTROY` | 按原版公式逐 tick 累计进度；按手持工具计算掉落；扣 1 点耐久；`#tlmm:protected` 拒绝 |
| `place_block` | `MODIFY` | 先 `canSurvive` 再落块；占用返回 `blocked` 且不吞物品 |
| `withdraw_items` | `MODIFY` | 直接读写 `Container` 槽位，不弹 GUI；背包满时把溢出放回原容器 |
| `deposit_items` | `MODIFY` | 先合并同类再填空槽，返回实际存入数量 |
| `move_slot` | `MODIFY` | 单槽原子搬运，`isSameItemSameComponents` 判等，目标槽有异物则 `blocked` |
| `craft_item` | `MODIFY` | 遍历真实配方表，先虚拟预占材料再提交；有序与无序配方均支持 |
| `smelt_items` | `MODIFY` | 只搬输入/燃料/产物三个槽，熔炼由原版方块实体推进 |

工具授权（`Tools`）：

- 每次 `check` 重新读背包与手持，不缓存。
- 需要正确工具但没有工具 → `tool_not_in_inventory`；工具等级不足 → `wrong_tool`；
  作业中工具被拿走或替换 → `tool_lost`；剩余耐久 < 10 → `tool_lost`。

## 3. 已知边界

- 未使用「非注册 ServerPlayer」代理：本轮放置走 `canSurvive` + `setBlock`，合成走
  `CraftingInput` + 真实配方，熔炼走熔炉方块实体。三者都不需要 Player 上下文，
  因此没有引入假玩家，也就没有污染在线人数或保护插件的风险。设计文档 §9 的假玩家方案
  保留为将来需要 `BlockItem.place` 特殊语义时的备选，而不是当前依赖。
- `withdraw_items` / `deposit_items` 暂无「登记仓库」归属判断；容器归属规则随 M6.5
  的机会识别与保护区一起落地。
- 合成不支持需要工作台专用 `RecipeType` 的自定义配方，返回 `missing_item`。
