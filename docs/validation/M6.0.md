# M6.0 模块框架验收

日期：`2026-11-21`

范围：`ActionModule` 契约、`Plan` 编解码、`PlanGate` 静态校验、`PlanRunner` 逐 tick 执行、
聊天事件流、`/tlmm debug plan` 开发入口。

## 1. 实现

`core`（纯 Java，无 Minecraft 依赖）：

- `ActionModule` / `ModuleSpec` / `ParamSpec` / `ModuleParams` / `ModuleExecution`。
- `Plan` / `PlanStep` / `FailurePolicy` / `RepeatSpec` / `PlanJson`：未知字段、未知模块名、
  超长文本一律解析失败，不做「猜测式修复」。
- `PlanGate`：模块白名单、参数类型与范围、风险档、动作/时长/破坏预算、绑定顺序、
  谓词白名单；计划体积上限 16KB、24 步、400 动作、12000 tick、128 破坏。
- `PlanRunner`：一次一个模块、每 tick 推进一步、`abort / continue / retry:N`、`repeat` 上限 8、
  `bind` 输出供后续 `$name` 引用、取消语义。
- `PlanPredicate`：仅 11 种固定形式，无通用表达式求值。

`fabric`：

- `SayModule`、`GotoModule` 两个真实模块。
- `PlanRuntime`：提交前过闸门，之后每 tick 推进；进度写入现有 `EventBus`
  （`plan_started / step_started / step_finished / plan_finished`），不新增 MCP 工具。
- `/tlmm debug plan <json>`、`/tlmm debug plancancel`。

## 2. 验证

```powershell
$env:JAVA_HOME="C:\Users\litou\.jdks\jdk-25.0.5.1+2"
$env:PATH="$env:JAVA_HOME\bin;$env:PATH"

.\gradlew.bat :core:test
.\gradlew.bat :fabric:runGameTestServer
```

结果：

- `:core:test` 通过，新增 `PlanJsonTest`、`PlanGateTest`、`PlanRunnerTest`、
  `PlanPredicateTest` 共 37 个用例（含 5 类非法计划、重试上限、绑定顺序、重复预算）。
- `:fabric:runGameTestServer`：`55 GAME TESTS COMPLETE` / `All 55 required tests passed`。
  新增 5 条 M6 用例：
  - `sayAndGotoPlanFinishesInOrder`：两步计划跑通，事件流严格为
    `plan_started → step_started → step_finished → step_started → step_finished → plan_finished`，
    且 `ok:true`。
  - `unknownModuleIsRejectedBeforeStarting`：`shell_exec` 返回 `unknown_module`，不建会话。
  - `overBudgetPlanIsRejected`：24 × 60 秒的 `goto` 返回 `budget_exceeded`。
  - `gotoKeepsTickingWithoutBlocking`：3 格行走在两 tick 后仍在运行，未同步完成。
  - `secondPlanIsRejectedWhileOneIsRunning`：并发计划返回 `busy`。

## 3. 已知边界

- `DESTROY` 模块在 `command` 档需要显式确认（`Policy.commandConfirmed()` 才放行）；
  未做二次确认 UI，属于 M6.4 范围。
- `step.ok("<id>")` 里的 id 指该步的 `bind` 名称；没有 bind 的步骤不能被谓词引用。
- `replan_on`（失败重规划）尚未实现，当前失败即按 `on_failure` 结束。

## 4. 结论

**Go**：计划是可静态校验的数据，执行不阻塞主线程，非法计划在运行前被拒。
