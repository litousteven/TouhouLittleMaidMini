## 5. 阻塞项与根因

### 5.1 OpenGL 后端原生崩溃

现象：`runClient` 与 `runClientGametest` 在 GUI 初始化阶段以
`exit value -1073741819 (NTSTATUS 0xC0000005)` 退出，无 Java 异常、无 crash report。

根因：本机 OpenGL 上下文报告为 `3.3.0 Core Profile`（RX 7900 XT 预期为 4.6），
Minecraft `26.3` 的 `renderpearl` 渲染层在该驱动路径下发生原生访问冲突。

处理：Minecraft `26.3` 支持 `--graphicsBackend` 启动参数。`fabric/build.gradle` 新增可选
Gradle 属性 `tlmm.graphicsBackend`，仅在显式传入时转发该参数：

```powershell
.\gradlew.bat :fabric:runClient -Ptlmm.graphicsBackend=vulkan
.\gradlew.bat :fabric:runClientGametest -Ptlmm.graphicsBackend=vulkan
```

验证：不传该属性时仍崩溃（OpenGL），传 `vulkan` 时渲染通过（`Using graphics backend
Vulkan … AMD proprietary driver 26.9.2`）。这是一次干净状态的对照实验，截图与
`options.txt` 均已预先删除。

该参数不影响 CI 或未受影响的机器：默认行为与之前一致。

### 5.2 MCP 依赖结论

Numen `v0.1.5-26.3-beta` 未找到公开 Maven 坐标。M0 使用项目自身的最小纯 JVM MCP 层
（`mcp` 模块，无 Minecraft 依赖）。vendor Numen `mcp` 模块或继续维护该最小层的取舍留到
M2 决定。

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8765/mcp" -Method Post -Headers $h `
  -Body '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

## 7. Go/No-Go

- Go：平台、依赖、客户端渲染、GameTest、MCP 与停服清理全部通过。
- 已知环境约束：本机开发客户端需 `-Ptlmm.graphicsBackend=vulkan`；这是本机 OpenGL 驱动
  问题，不是模组缺陷，不进入产品边界。
- 未决但不阻塞：NeoForge GameTest 在补 `EntityAttributeCreationEvent` 后尚未重跑；按当前
  优先级不作为 M0 门禁。
