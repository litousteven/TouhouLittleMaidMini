## 结论

**实现与可重复验收全部通过；0.2 正式发布门禁未全部完成，因此不宣称 0.2 发布验收通过、
不创建 `v0.2` tag、不执行关机。** 另按 `2026-11-22` 用户指令，在基础验收复跑通过后
发布 `v0.1.1-beta` pre-release（0.1.x beta 线的功能预览，见 §6.1）。

M6.0–M6.7 的代码、单测、GameTest、客户端 E2E、语言键、打包和静态门禁都是绿的。
但 `docs/02-development-plan.md` M6.7 与 `docs/validation/M4.md` 明确规定两项只能由发布
操作者在目标环境完成的门禁：**24 小时浸泡** 与 **干净 VM 按 README 30 分钟跑通**。
本会话无法产生 24 小时的真实趋势数据，也不能把一次 3 秒的 GameTest 批次当作浸泡结果。
因此最终判定是「实现完成、短时验收通过、发布待门禁」。

## 2. 可重复验证

```
./gradlew :core:test :mcp:test :llm:test    → 276 个用例（core 182 / mcp 79 / llm 15），
                                            0 失败、1 项按设计跳过
./gradlew :fabric:runGameTestServer          → All 114 required tests passed
./gradlew :fabric:runClientGametest -Ptlmm.graphicsBackend=vulkan
                                            → 4 个客户端 GameTest 类通过（真实模型、
                                               自主回合、模板界面状态同步）
./gradlew :fabric:verifyTranslations         → 147 键一致
./gradlew :fabric:verifyClientOnlyModel      → 通过（服务端源码无模型客户端引用）
./gradlew clean build                         → BUILD SUCCESSFUL（28 个任务）
                                             :fabric:verifyPackagedMod 内含 core/mcp/llm
python scripts/verify-packaged-jar.py <jar>  → 322 个自有类 / 241 个 MC 符号全部可解析，PASS
```

客户端 GameTest 在本机 AMD Vulkan 驱动下仍有约 1/3 概率于 unifont 加载阶段以
`0xC0000005` 原生崩溃（与模组代码无关）。清理 `run/clientGametest/options.txt` 与截图
缓存后重试即可；`docs/09-known-limitations.md` 已记录。此外客户端测试必须结束在标题
界面，`M6LearningClientGameTests` 因此显式切回 `TitleScreen`。本次运行未设置
`TLMM_MODEL_KEY`，M6.4 的真实模型分支按设计跳过；该分支在 [M6.4](M6.4.md) 已用
`sensenova-6.8-flash` 实跑通过。M6.5 的自主回合用本机 HTTP stub，可重复且不需要外网。

## 3. 性能探针（M6.7）

`M6ReleaseGameTests` 实测（测试服、无真实玩家负载）：

```text
[m6.7] tidy planning containers=20 worst=746us budget=5000us
[m6.7] concurrent=4 mspt_avg=0.502664 mspt_max=37.1179 heap=758/8092MB
       threads=35 events=186
```

- `fourConcurrentPlansFinishWithinTheTickBudget`：4 名同伴同时跑 2 步计划，
  `PlanRuntime.activeCount() >= 4`，四个会话均正常结束并记录 `plan_finished(ok=true)`；
  同时打印 `ServerDiagnostics` 的 MSPT / 堆 / 线程 / 事件积压，平均 MSPT 预算 50。
- `planningTwentyChestsStaysUnderFiveMilliseconds`：20 个 27 槽容器预热后连测 10 次，
  取最坏一次，断言单次确定性规划 < 5ms。
- `mspt_max` 的 37ms 尖峰来自同批 GameTest 并发启动，不是计划本身；平均值 0.50ms
  远低于 50ms 预算。该数值仍只是下限参考。

这两项是**单帧算法与并发正确性**的下限检查，不是 24 小时长稳结论。生产服的
「4 名同伴并行计划，MSPT 增量 < 1.0」必须由 `scripts/soak.ps1 -Minutes 1440` 在目标
专用服上按 `docs/03-testing-and-debugging.md` 的矩阵测量。

### 3.1 短时浸泡（0.2 工具链复验）

在专用服设置临时 `TLMM_MCP_TOKEN` 后运行 `scripts/soak.ps1 -Minutes 2
-IntervalSeconds 15`，原始 CSV 见 [`assets/m6/soak-m6-short.csv`](assets/m6/soak-m6-short.csv)：

```text
Samples: 8 (0 failed, 0%)
Heap: first=256MB last=261MB max=261MB growth=5MB
Heap trend (first/last 25% mean): 258MB -> 261MB = 3MB
Threads: first=36 last=38 growth=2 trend=1
```

停止服务器后 `8765` 与 `25565` 均无监听、无残留 Java 进程。该结果只证明浸泡脚本与
0.2 服务端配合正常，**不替代 24 小时趋势判定**。

## 4. 与最初设计的逐条核对

| 章程 / 设计条款 | 现状 | 说明 |
|---|---|---|
| §3.1 薄身体：实体、寻路、观察、权限、审计在 Java | 符合 | M0–M3 已验证；M6 未把安全逻辑交给模型 |
| §3.2 通用动作面向能力，不按玩法新增 Java Task | 符合 | 15+1 个模块全为能力；`pickup_items` 是能力补齐，不是新玩法 |
| §3.3 三脑：基础脑无需模型、外部 MCP 脑、客户端脑持 Key | 符合 | `verifyClientOnlyModel` 保证服务端无模型请求路径 |
| §3.3 模型只提交「模块序列 + 参数」，服务端逐条校验 | 符合 | `PlanJson` → `PlanGate` → `PlanRuntime` 三处复验 |
| §3.3 模型不可用 / 断线 / 拒绝时回到基础脑 | 符合 | 断线取消名下计划；无 Key 客户端直接拒绝 |
| §3.4 Skill 优先，Markdown / 结构化数据，不生成代码 | 符合 | `SkillLoader` 三级加载；模板只存模块序列与占位符 |
| §3.4 学习产物需玩家确认保存 | 符合 | 提案 PENDING → 采纳才可执行，前两次仍需确认 |
| §3.5 数据优先：标签 / ID / 规则表达作物、敌对、容器 | 符合 | `SemanticTags` 六档优先级 + 知识叠加层 + 人工确认 `hostile` |
| §3.6 AI 决定「做什么」，不能决定「是否有权做」 | 符合 | 档位白名单、保护区、工具即授权、预算/熔断均在服务端 |
| §10 自主模式候选压到 0–4 条，模型只做选择题 | 符合 | `OpportunityScanner` + `consumeOpportunity` + 模块匹配复验 |
| §11.4 熔断：暂停 / 主人受击 / 生命<30% / 3 连败停机 15 分钟 | 符合 | `/tlmm ai pause|resume`、伤害事件、预算熔断 |
| §12 学习闭环：提案可采纳 / 拒绝 / 回滚，失败降级 | 符合 | `TemplateCatalog` 状态机 + 审阅 UI |

| §14.1 场景 B（收菜+补种+熔炼+入库） | **部分** | 收割/补种/熔炼/入库各有 GameTest，客户端自主回合走完整条计划链路；未把四步合成一次自主计划实跑 |

## 5. 从 `0.1.0-beta` 迁移到本工作线

本节描述的 M6 功能线以 `v0.1.1-beta` pre-release 发布；`0.2` 正式版待 §6 门禁关闭后
再定版。下列变更对 `v0.1.1-beta` 同样适用。

- **模型凭据移动**：服务端 `config/tlmm/credentials.key`（M5）不再读取；服务端
  `[llm]` 配置段被忽略，加载时只打印一句提示，不删除用户文件、不打印任何值。请在客户端
  `AI 设置` 页填写 base URL / model / API Key，或写入
  `run/client/config/tlmm-client.toml` 与 `config/tlmm/credentials.key`。
- **新增服务端配置** `config/tlmm-autonomy.toml`（`tier = "off|suggest|chores|free"`，
  默认 `chores`）。采石/伐木类机会只在 `free` 档生成。
- **新增持久化目录**：`config/tlmm/learning/templates.json`（模板提案与信任状态）、
  `config/tlmm/skills/`（用户 Skill 覆盖 `skills/builtin/` 中的内置副本）、
  `config/tlmm/knowledge/`（沿用 M6.3b）。首次启动自动创建，可安全删除以重置学习状态。
- **新增命令**：`/tlmm autonomy ...`、`/tlmm ai pause|resume|status`、
  `/tlmm template ...`。旧的 `/tlmm llm *` 已删除。
- **协议**：`agent_submit_plan` 增加 `source`、`tokens`；新增 S2C
  `agent_opportunities`、`template_view`；`agent_request_observation` 的 category 上限
  提到 256 并支持 `skill:` / `skill_file:`。旧客户端与 0.2 服务端不兼容，需同步升级。
- **打包**：jar 内含 `core`、`mcp`、`llm`；NeoForge 仍可编译但未验证、不发布。

## 6. 0.2 正式发布门禁（未关闭，不得打 `v0.2` / 关机）

1. **24 小时浸泡**：在目标专用服启动 0.2，按
   `scripts/soak.ps1 -Minutes 1440 -Token <token>` 采样，确认无堆/线程趋势增长、
   无端口残留、无任务泄漏，4 名同伴并行计划时 MSPT 增量 < 1.0。
2. **干净 VM**：按 `docs/07-installation.md` 在全新环境 30 分钟内跑通。
3. 门禁通过后：更新 `docs/validation/M6.md` 的结论与数据，写
   `docs/releases/v<version>.md`，在 `gradle.properties` 定版并推送 `v<version>` tag，
   由 `.github/workflows/release.yml` 生成 Release（附件只放 Fabric jar，默认 pre-release）。

在这三项完成前，0.2 不正式定版、不创建 `v0.2` tag，也不执行用户最初要求的
「完整测试验收后关闭电脑」。
