### 2.2 `0.1.0-beta` 实际具备的能力

- `/tlmm summon|remove|rename|home|behavior|diag`，9 格背包 + 6 格装备。
- 本地行为 `stay / follow / guard`，M5 增加 `farm`；`all / day / night` 日程。
- 右键管理界面（176×240）、原创皮肤、占位模型与行走动画、中英双语。
- MCP `127.0.0.1:8765/mcp`，Streamable HTTP + Bearer，10 个工具。
- 七类上下文、事件长轮询、按同伴签发/撤销 Token、只读作用域、幂等、审计、限流、
  破坏性动作的真人授权。
- `farm` 按 `CropBlock` 语义收割成熟作物并用背包种子补种，已由 GameTest 验证。

### 2.3 已知遗留

- 模型只能输出四种行为与 Skill 提案，不能编排多步动作。
- 服务端仍保存模型 Key 并发起请求；`0.2` 要迁到客户端。
- `farm` 直接判 `CropBlock`，未走统一语义解析；模组新增作物不一定被识别。
- 没有箱子整理，没有工具授权门控。
- 没有真实的 OpenAI 兼容服务 E2E；仅由模拟传输覆盖。
- 通过 `/tlmm llm token` 写入时，若服务器显式开启命令日志，Token 可能进入外部日志。

## 3. 0.2 计划

### 3.1 目标

在 `0.1.0-beta` 的身体与 MCP 之上，交付三件事：

1. **有界计划执行**：模型提交"模块序列 + 参数"，服务端静态校验并逐条执行；不引入
   解释器与任意脚本。
2. **客户端脑**：模型调用与 Key 只存在玩家客户端；服务端只做校验、执行与审计。
3. **自动适配模组**：语义分类叠加层 + 模型标注，让新作物、食物、工作站、敌对生物
   在没有专用 Java 代码时也能被识别。

同时补齐两项基础能力：**箱子整理**（同类归并，参考铜傀儡）与**工具即授权**
（背包里有什么工具，才做什么活）。

### 3.2 非目标

- 不做 Lua/JS 或任何宿主级执行；不做模型训练。
- 不做无界挖建、不做任意模组 GUI 自动化。
- 不在服务端保存 Key、不在服务端发起模型请求。
- 不为每种作物、模组或工作新增 Java 模块。
- NeoForge 与 TLM 适配顺延，不阻塞 `0.2`。

### 3.4 各阶段任务与验收

#### M6.0 模块框架

任务：

- `core`：`ActionModule` 接口、`ModuleSpec` 参数 schema、`Plan` 记录、`PlanGate`、
  `PlanRunner`、统一失败码枚举、预算计算。
- 计划静态校验：步骤数、动作数、时长、破坏方块数、风险等级、模块白名单。
- 开发入口：OP 命令 `/tlmm debug plan <json>`，用于手工与 GameTest 触发；不新增 MCP 工具。
- 执行语义：一次一个模块，每步产出 `ModuleResult`；失败按 `abort / continue / retry`
  处理，`retry` 上限 1 次。

验收：

- `say` + `goto` 两步计划跑通，事件流出现 `plan_started / step_started /
  step_finished / plan_finished`。
- 以下计划被拒且返回具体原因：未知模块、参数类型错误、超出预算、`DESTROY` 级模块在
  `chores` 档、计划体超过 16KB。
- 计划执行不阻塞服务端主线程：单 tick 内不等待寻路完成。

不做：条件分支语言、循环、变量、表达式求值。

#### M6.1 身体能力

任务：

- 挖掘：按工具等级与硬度累计进度，扣耐久，按等级掉落。
- 放置：`BlockPlaceContext`，处理朝向、碰撞、含水、可替换。
- 容器读写：`Container` 槽位直接读写，不弹 GUI；上锁容器拒绝。
- 槽位搬运：单槽原子取出/放入，按 `isSameItemSameComponents` 合并。
- 合成与熔炼：`RecipeManager` 匹配、消耗、产出；熔炉按原版 tick 推进。
- 工具前置：`requiredTool`、等级比较、耐久阈值；`tool_not_in_inventory` 与
  `wrong_tool` 分开。
- `Player` 上下文代理：不注册进玩家列表的 `ServerPlayer`，位置朝向每 tick 同步。

验收（每个能力至少一条 GameTest）：

- 徒手挖石头返回 `tool_not_in_inventory`（没有工具），木镐挖铁矿返回 `wrong_tool`
  （等级不够）；石镐挖石头成功，掉落物进背包。
- 放置方块时目标被占用返回 `blocked`，不吞物品。
- 从箱子取 1 组放入背包，数量守恒；上锁容器返回 `locked`。
- 2×2 与 3×3 合成各一条；缺材料返回 `missing_item`。
- 熔炼产出在预期 tick 后出现，燃料消耗正确。
- 工具在作业中被移除，下一步返回 `tool_lost`。

#### M6.2 模块库

任务：

- 生产模块全部走 `SemanticTags`，不出现具体作物或矿物 ID。
- `tidy_chests`：索引 → 规划 → 执行 → 校验；跳过玩家 5 格内开启的箱子、`#tlmm:keep`、
  他人容器；保留 ≥1 空箱；预算 200 槽位 / 120 秒；中断后先卸货。
- `till_area` 需要锄，属 `free` 档或命令，不进 `chores`。

验收：

- 收割：成熟收割、未成熟跳过、补种消耗正确种子、背包满返回 `inventory_full`。
- 采石：按标签选点，不破坏家半径 16 格内方块，耐久按次扣减。
- 整理：3 个杂箱合并后同类集中、空出 ≥1 箱、数量守恒；人为制造不一致时返回
  `count_mismatch` 并中止。
- 所有模块在 `0.1.0-beta` 的 50 个 GameTest 上无回归。

#### M6.3 语义底座

任务：

- `SemanticTags` 六档优先级：真实数据 → 真实标签 → 玩家 → 模型 → 启发式 → unknown。
- 封闭枚举 `SemanticTag`（17 个值），按 `kind` 解释。
- 启发式：`CropBlock`/`age` 判作物、`FOOD` 组件判食物、燃烧值判燃料、
  `Container` + 配方类型判工作站、`Monster` 判敌对。
- 知识文件：`config/tlmm/knowledge/<namespace>.json`，`entries` / `pending`，原子写入。
- `FarmGoal` 改为走 `SemanticTags`，删除硬编码判定。

验收：

- 未分类方块让 `farm` 返回 `unknown_category`，不静默跳过。
- 关掉模型配置，启发式仍能识别原版小麦与测试作物。
- 写入一条与真实标签冲突的分类，解析器忽略该条并记录 `tag_conflict`。

#### M6.3b 标注闭环

任务：

- `UnknownContentScanner`：只扫背包、64 格内方块实体、登记容器、近期配方。
- 批量清单（≤64 项）+ 客户端补本地化名 + 严格响应 schema。
- `KnowledgeValidator`：id / kind / tag / 冲突 / 置信度 / 用户锁定。
- 审阅 UI：新增、待确认、单条撤销、批次回滚、导出数据包。
- `hostile` 只入 `pending`，确认后生效；硬排除玩家、村民、有主宠物、命名生物。

验收：

- 装 Farmer's Delight 后自动补全白菜与厨锅，`farm` 与 `cook_food` 可用。
- 低置信度条目进 `pending`，不影响行为。
- 写入错误 food 分类后喂食被真实 `FOOD` 组件拦下。
- `hostile` 提案未确认时不出现在 `guard` 目标集。
- `/tlmm knowledge undo <batch>` 能整批回滚。

#### M6.4 客户端脑

任务：

- 配置迁移：`config/tlmm-client.toml` + `config/tlmm/credentials.key`；服务端 `[llm]`
  标记废弃，只提示、不打印值、不自动删除。
- `AgentLoop`：组上下文 → 调模型 → 解析 `Plan` → 本地快校验 → 提交。
- 网络包：`submit_plan` / `cancel` / `request_observation` / `knowledge_*` 与 4 个 S2C 包。
- UI：Chat 页、任务卡、能力行、模组内容页。
- 删除服务端 `LlmRuntime` 的模型请求路径。

验收：

- 真实模型完成一次"收门口那片小麦"的对话任务，计划被服务端接受并执行。
- 服务端日志、审计、配置中无 Key；抓包确认无出站模型请求。
- 断线后同伴停计划、回基础行为，服务端无残留任务。
- 伪造的越权计划被 `PlanGate` 拒绝；超频提交被限流。

#### M6.5 自主模式

任务：

- `OpportunityScanner`：6 类机会 + 前置条件（含工具）。
- 导演循环：0–4 条候选 → 模型选择题 → 计划；`none` 合法。
- 仲裁：紧急反射 > 主人受击 > 命令 > 跟随 > 自主 > 闲逛。
- 熔断：`/tlmm ai pause`、生命 < 30%、连续失败 3 次、15 分钟冷却。

验收：

- 场景 A：主人放 ≥32 圆石、箱内不足、背包有镐 → 采石入库；无镐不生成机会。
- 场景 B：20 株成熟 + 生食燃料 → 收菜、补种、熔炼、入库，聊天栏有结果。
- 场景 C：3 个杂箱 → 整理完成，保留箱与玩家正开的箱子未动。
- 刷怪中断后清怪 90 秒才重新评估；连续失败 3 次后 15 分钟不自主。

#### M6.6 学习闭环

任务：

- 成功计划 → 模板提案（模块序列 + 参数占位符）→ 玩家审阅 → 监督执行 2 次 → trusted。
- 连续失败 3 次降级回 supervised；不自动执行未审阅模板。
- Skill 三级加载：索引 → 正文 → 附属文件，禁止越出目录。

验收：

- 提案可采纳、可拒绝、可回滚；采纳后前两次执行需确认。
- 失败 3 次后自动降级，UI 状态同步。

#### M6.7 发布验收

任务：性能剖析、24 小时浸泡、迁移说明、已知限制更新、`docs/validation/M6.md`。

验收：

- 完整构建通过；jar 包含 `core`、`mcp`、`llm`。
- 4 名同伴并行计划，MSPT 增量 < 1.0；整理 20 箱单帧 < 5ms。
- 24 小时浸泡无堆/线程趋势增长、无端口残留、无任务泄漏。

### 3.6 门禁

- 任一阶段验收失败：保持未完成，不加阶段完成提交；修根因，不降断言。
- `M6.0` 之后计划 schema 变更必须带版本号与迁移说明。
- `M6.4` 完成后，服务端不得存在任何模型出站路径；代码搜索 `llm` 在 `fabric` 侧应为空。
- `M6.5` 之前不得对外宣称"自主"；文档只能写"计划执行"。

## 4. 测试与验收

测试命令、环境与调试入口见 [`03-testing-and-debugging.md`](03-testing-and-debugging.md)。
本节只定义**验什么、通过标准是什么**。

### 4.1 分层

| 层 | 范围 | 运行方式 | 门禁 |
|---|---|---|---|
| L1 纯 JVM | 计划校验、语义解析、知识文件、配置迁移、失败码 | `:core:test :llm:test` | 必须全绿，无网络 |
| L2 GameTest | 实体、身体能力、模块、整理、工具授权、知识生效 | `:fabric:runGameTestServer` | 必须全绿，含 12 同伴性能探针 |
| L3 客户端 | 界面、能力行、模组内容页、聊天 | `:fabric:runClientGametest` | 通过 + 截图人工检查 |
| L4 E2E | MCP 协议、真实服务端、真实模型 | 独立 `run/e2e` | 每个里程碑一条可复现脚本 |
| L5 长稳 | 性能、24 小时浸泡 | `scripts/soak.ps1` | 趋势与失败率达标 |

### 4.2 L1 必测项（0.2 新增）

- `PlanGate`：未知模块、参数越界、超步数、超预算、风险档不匹配、体积超限。
- `PlanRunner`：失败 `abort/continue/retry`、`retry` 上限、中断后状态。
- `SemanticTags`：六档优先级、真实标签不可覆盖、`kind` 错配、`unknown_category`。
- `KnowledgeValidator`：`unknown_id`、`kind_mismatch`、`bad_tag`、`tag_conflict`、
  `user_locked`、低置信度降级。
- 知识文件：原子写入、坏文件回退、批次回滚。

## 5. 完成定义与提交门禁

一个功能同时满足以下条件才算完成：

- 有强类型模块契约，不依赖文本 JSON 作为内部接口。
- L1 有单测；涉及实体或世界修改时有 GameTest。
- 成功、拒绝、超时、中断都有明确失败码。
- 不阻塞服务端主线程；异步操作可取消。
- 权限、保护区、工具前置在服务端裁定，不依赖客户端。
- 日志不含 Key、完整背包、对话正文。
- 设计文档、语言文件、配置示例同步更新。

提交门禁：

1. `git diff --check` 通过。
2. 本阶段验收命令全部通过并记录。
3. 只暂存本阶段相关文件，不夹带无关改动。
4. 阶段完成提交使用 Conventional Commit，正文列出验证命令与结果；不用 amend 掩盖失败。
